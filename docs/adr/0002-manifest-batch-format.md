# ADR-0002: manifest 批量导入格式

- **状态**：已批准（wayfinder ticket #6「定义 manifest 批量导入格式」）
- **日期**：2026-08-06
- **范围**：执行规范，不改代码。批量导入解析器与「待确认」入口的实现依据。

## 背景

发布页 UI 为主 + manifest 批量导入保留（D10）。批量导入让运营人员把一批「视频 + 文案 + 排期」准备好，一次导入、一次核对、一次放行。本 ADR 定义 manifest.json 的真实使用场景与格式。

## 使用场景

**一个批次 = 一个账号下的若干视频。** 运营人员的操作是：准备一个文件夹（若干视频 + 一个 `manifest.json`）→ 在 PostHub 导入 UI **选定目标账号** → 校验 → 待确认列表核对 → 确认后生成任务。

关键结论（来自 grilling）：

1. **账号在导入 UI 选定，manifest 不含账号字段。** 账号不是 manifest 里的自由文本，而是导入动作的输入——「在该账号下执行上传」。因此 manifest 没有 `accounts` / `platforms` 字段（草案原有，已移除）。
2. 一个批次只绑定一个账号。多账号 = 多次导入（如视频号 5 条、抖音 3 条、视频号2 5 条 = 3 个批次，各选各的账号）。
3. 一次导入展开为多个任务：manifest 中每个条目生成一个任务（task），发布到该账号所属平台。
4. **导入不直接排队**，先进「待确认」列表：运营者逐条核对（标题/时间/账号/文件）后再放行。

## 格式

文件夹结构：

```
一批次文件夹/
├── 视频1.mp4
├── 视频2.mp4
├── cover1.jpg              ← 封面可选，横竖版分开
└── manifest.json
```

`manifest.json` 顶层是一个对象，`videos` 为条目数组：

```json
{
  "version": 1,
  "videos": [
    {
      "file": "视频1.mp4",
      "title": "标题",
      "content": "正文",
      "tags": ["话题1", "话题2"],
      "cover_landscape": "cover1.jpg",
      "cover_portrait": "",
      "schedule": "2026-08-08 10:00:00"
    }
  ]
}
```

## 字段语义

| 字段 | 必填 | 语义 |
|---|---|---|
| `file` | 是 | 相对 manifest 所在目录的路径，支持子目录；同批内文件名唯一 |
| `title` | 可空 | 空时用文件名（去扩展名）兜底 |
| `content` | 否 | 正文/描述 |
| `tags` | 否 | 话题/标签字符串数组；小红书超 10 个软提示（平台截断） |
| `cover_landscape` | 否 | 横版封面相对路径；空则走平台默认（抖音自动选推荐封面） |
| `cover_portrait` | 否 | 竖版封面相对路径；空则走平台默认 |
| `schedule` | 否 | 定时时间，`YYYY-MM-DD HH:mm:ss`；不写 = 立即发布 |
| `version` | 顶层 | 格式版本，当前 1 |

`schedule` 校验区间：**≥2h 且 ≤7 天**（调研 #9：三平台最大提前量均约 7 天，官方均无明文）。超 7 天报错并提示可改「立即发布」；不足 2h 报错。

## 校验与冲突处理

导入时分级处理：

| 情况 | 处理 |
|---|---|
| JSON 语法错误 / `version` 不支持 | 硬报错，整批拒绝，列出问题 |
| `file` 不存在 / 同批内文件名重复 | 硬报错 |
| `title` 超平台上限（抖音 30 / 小红书 20） | 硬报错 |
| 封面路径不存在 | 硬报错 |
| `schedule` 超出 2h–7 天 | 硬报错 |
| `tags` 超 10 个（小红书） | 软处理，进待确认并黄色标注 |
| `title` 为空 | 软处理，用文件名兜底并提示 |

原则：**会导致发布失败或明显违背意图的硬报错；平台会静默截断或可兜底的软提示进待确认。**

## 与 ADR-0001 的关系

- ADR-0001 的 `batch` 表（文件夹 + manifest.json）与本 ADR 一致，但 **缺少与账号的关联**。本 ADR 的模型「一个批次绑定一个账号」要求 `batch` 增加 `account_id` 外键（或由导入时创建的任务关联账号）。该调整属 ADR-0001 范围，本 ADR 不做修改，仅标注冲突。
- ADR-0001 的 `task` 表字段（title / caption / tags / cover_horizontal / cover_vertical / publish_at）与 manifest 条目一一对应，导入即按此映射生成 task。
